Full-Stack Development for absolute beginners

Every website you've ever used is built from the same three ingredients: structure, style, and behavior — plus something on a server keeping track of your data. This course walks through both halves, front and back, in plain language, building toward one real project: a page that talks to a tiny server.

01 What Is Full-Stack Development?

"Full-stack" just means you can work on both ends of a website: what people see, and what runs behind the scenes.

A website has two halves. The frontend is everything a visitor sees and clicks in their browser — text, images, buttons, layout. The backend is the part running on a server somewhere else, handling data: saving your profile, checking a password, storing an order.

  • Frontend: HTML (structure), CSS (style), JavaScript (behavior) — all run inside the visitor's browser.
  • Backend: a server program (often written in JavaScript via Node.js, or Python, or others) that stores and serves data.
  • Database: where information is kept long-term — user accounts, blog posts, product listings.
Don't worry Every term here is explained in full the first time it's used, in the section built for it. You don't need to know what an "API" or "the DOM" is yet — that's exactly what's coming.

02 How the Web Works

A website is just two computers passing messages back and forth.

When you type a web address, your browser sends a request asking a server "can I have this page?" The server sends back a response — usually an HTML file, plus the CSS and JavaScript it needs. This request/response exchange happens over HTTP (HyperText Transfer Protocol), the web's basic messaging rulebook.

the flow
// 1. You type an address and press Enter
browser.request("https://example.com");

// 2. The server finds and sends back the page
server.respond("index.html + styles.css + script.js");

// 3. Your browser draws it on screen — that's the page you see
Analogy Think of the browser as a customer at a counter, and the server as the kitchen. The customer orders ("give me this page"), the kitchen prepares it and hands it back. Every click on a link is a new order.

03 HTML: Structuring a Page

HTML (HyperText Markup Language) describes what's on the page — headings, paragraphs, images, buttons.

page.html
<!DOCTYPE html>
<html>
<head>
  <title>My First Page</title>
</head>
<body>
  <h1>Hello, world!</h1>
  <p>This is a paragraph of text.</p>
  <button>Click me</button>
</body>
</html>

HTML is built from tags like <h1> (a big heading) and <p> (a paragraph), almost always in opening/closing pairs that wrap the content they describe. The browser reads this file top to bottom and turns each tag into something visual.

Common tags <h1>–<h6> headings, <p> paragraph, <a href="..."> link, <img src="..."> image, <div> a generic box, <button> a clickable button.

04 CSS: Styling & Layout

CSS (Cascading Style Sheets) describes how things look — colors, fonts, spacing, and where elements sit on the page.

style.css
h1 {
    color: navy;
    font-size: 32px;
}

.card {
    background: #f5f5f5;
    padding: 16px;
    border-radius: 8px;
}

Each rule targets something (an h1 tag, or anything with class="card") and lists properties to change. A class is a label you give an HTML element so CSS (or JavaScript) can single it out: <div class="card">.

Laying things out: Flexbox

Modern layouts mostly use Flexbox — one property that turns a container into a row (or column) that lines up its children automatically.

layout.css
.row {
    display: flex;         /* children sit side by side */
    justify-content: center;
    gap: 1rem;
}

05 JS: Variables & Data Types

JavaScript is what makes a page do something instead of just sitting there. It runs both in the browser and, later, on the server.

variables.js
let age = 25;            // a number, can change later
const name = "Amal";     // text (a "string"), can't be reassigned
let isStudent = true;   // true or false (a "boolean")
let nothingYet = null;  // deliberately empty
TypeHoldsExample
NumberAny number, whole or decimallet price = 19.99;
StringText, in quoteslet city = "Tunis";
Booleantrue or falselet done = false;
ArrayAn ordered list of valueslet colors = ["red","blue"];
ObjectNamed key/value pairslet user = {name:"Amal"};
null / undefined"Nothing" / "not set yet"let x = null;
let vs const Use const by default — it means "this name won't be reassigned." Switch to let only for values you genuinely need to change later, like a counter.

Use ===, not == === compares value and type strictly — the safe default. Plain == silently converts types before comparing and causes surprising bugs.

07 Functions in JavaScript

functions.js
function add(a, b) {
    return a + b;
}

const multiply = (a, b) => a * b;   // "arrow function" — a shorter way to write one

console.log(add(2, 3));        // 5

A function is a named, reusable block of code. It can take parameters (the inputs, like a and b) and return a result. Arrow functions (=>) are just a shorter way to write the same idea, used constantly in modern JavaScript.

08 Arrays, Objects & JSON

data.js
const colors = ["red", "green", "blue"];
console.log(colors[0]);       // "red" — arrays start counting at 0

const user = {
    name: "Amal",
    age: 25,
    isStudent: true
};
console.log(user.name);   // "Amal" — "." reaches inside the object

An array is an ordered list. An object is a bundle of named properties — very similar to a struct in C, if that's familiar. JSON (JavaScript Object Notation) is just this object syntax used as a plain-text format — it's how the frontend and backend send structured data to each other, which comes back in section 14.

09 The DOM: Interactive Pages

The DOM (Document Object Model) is how JavaScript "sees" and changes the HTML on the page, live.

interact.js
const button = document.querySelector("button");

button.addEventListener("click", () => {
    document.querySelector("h1").textContent = "You clicked it!";
});

document.querySelector(...) finds an element on the page. addEventListener("click", ...) says "when this is clicked, run this function." This one pattern — find something, listen for an event, change something — is behind almost every interactive website you've used.

10 Git & GitHub

Git tracks every change to your code over time. GitHub hosts that history online so you can share and collaborate.

terminal
# save your changes as a labeled checkpoint
git add .
git commit -m "Add homepage"

# send that checkpoint to GitHub
git push

Think of a commit as a save point you can always come back to, with a note describing what changed. A repository ("repo") is a project's full folder of code plus its entire history. This whole academy site, in fact, lives in one.

11 Node.js: JavaScript on the Server

Node.js lets JavaScript run outside the browser — on a server, where it can read files, talk to databases, and respond to requests.

server.js
const http = require("http");

const server = http.createServer((req, res) => {
    res.end("Hello from the server!");
});

server.listen(3000);   // now listening on http://localhost:3000

This is the "backend" from section 1 made real: a program that stays running, waiting for requests, and responding to each one. Frameworks like Express (next section) make writing this kind of code much shorter.

12 Building a Simple API

An API (Application Programming Interface) is a defined set of URLs a server responds to — the "menu" your frontend can order from.

api.js
const express = require("express");
const app = express();

app.get("/api/users", (req, res) => {
    res.json([{ name: "Amal" }, { name: "Sami" }]);
});

app.listen(3000);

app.get("/api/users", ...) says "when someone requests this exact URL, run this function and send back JSON." Real APIs also handle POST (create something new), PUT (update), and DELETE — together these four cover almost everything a website needs to do with data.

13 Databases, Briefly

A database is where data survives after the server restarts — user accounts, posts, orders.

KindIdeaExamples
SQL (relational)Data in strict tables with rows and columns, like a spreadsheet with rulesPostgreSQL, MySQL, SQLite
NoSQL (document)Data stored as flexible JSON-like documentsMongoDB
query.sql
SELECT name, email FROM users WHERE age > 18;

You don't need to master databases to start — just know that the backend's job, most of the time, is reading from and writing to one of these on your behalf.

14 Connecting Frontend to Backend

The moment it all clicks together: the browser asking the server for data, with JavaScript's fetch.

fetch.js
fetch("/api/users")
    .then(res => res.json())         // turn the response into usable JS data
    .then(users => {
        console.log(users);             // [{name: "Amal"}, {name: "Sami"}]
    });

This is the whole loop from the hero diagram, written out: the browser fetches a URL, the Node.js/Express server (section 12) answers with JSON pulled from a database (section 13), and the frontend uses that data to update the page (section 9).

15 Deploying Your Project

"Deploying" means putting your project on a server the whole internet can reach, instead of just your own computer.

  • Static sites (HTML/CSS/JS only, no server code) — services like GitHub Pages, Netlify, or Vercel host them for free.
  • Full apps with a backend — services like Render, Railway, or a VPS run your Node.js server continuously.
  • Domain name — optional, but it's what turns a long hosting URL into something like yoursite.com.
Good news This very academy site is a static HTML/CSS/JS site hosted straight from its GitHub repository — the simplest possible deployment, and a great first target to imitate.

16 What to Learn Next

You now have the full map — every advanced topic from here is a deeper look at one of these pieces.

  • A frontend framework — React, Vue, or Svelte make building complex interfaces far more manageable than raw JavaScript.
  • Authentication — how login, passwords, and sessions are actually handled securely.
  • TypeScript — JavaScript with types added, catching a whole category of bugs before they run.
  • Testing — writing code that checks your other code automatically.
  • Build tools — bundlers like Vite that prepare your code for production.
