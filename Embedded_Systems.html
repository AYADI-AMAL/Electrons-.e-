Embedded C for absolute beginners

You already know what a light switch does. By the end of this course you'll know how to write the code that is the switch — turning real hardware on and off with a language that talks straight to the chip. We'll go slow, explain every term the first time it shows up, and build toward one real project: blinking an LED.

1pin 1
0pin 2

This is a preview: four wires, one of them "on." By section 12 you'll know exactly what that means.

01 What Is Embedded C?

The same C language you'd learn anywhere — just aimed at tiny computers instead of laptops.

"Embedded" just means the computer is built into something else: a thermostat, a washing machine, a toy, a car's dashboard. These tiny computers are called microcontrollers, and C is the most common language for programming them, because it's small, fast, and lets you control hardware very precisely.

The good news: the C syntax itself — variables, loops, functions — is identical to C anywhere else. What's different is the environment around it:

  • There's usually no operating system. Your program is the entire thing running on the chip.
  • Memory is small — sometimes just a few thousand bytes, not gigabytes.
  • You often turn real things on and off: LEDs, motors, screens, sensors.
Don't worry If terms like "memory," "byte," or "register" feel fuzzy right now, that's normal — we define each one plainly the first time it comes up, and there's a glossary at the end you can jump back to any time.

02 What Is a Microcontroller?

A whole (tiny) computer on one chip.

A microcontroller is a single small chip that contains a processor (the part that runs your code), a little memory, and a set of pins — the little metal legs on the chip — that connect to the outside world. Some pins can be told "go high" (output electricity) or asked "are you high or low right now?" (read electricity). That's how code touches reality: by controlling voltage on a pin.

Popular examples you'll see mentioned around this topic: Arduino boards (which use microcontrollers from Atmel/Microchip), STM32 boards (ARM Cortex-M chips), and ESP32 boards. You don't need one to follow this course, but everything here is written so it transfers directly once you do.

Analogy Think of a microcontroller as a very small, very literal assistant. It has no imagination — it will do exactly what your code says, instruction by instruction, forever, starting the moment it gets power.

03 Your First Program

Every embedded C program has the same shape.

main.c
int main(void) {
    setup();          // runs once — prepare things

    while (1) {       // runs forever — the "main loop"
        loop();
    }
}

A few new words, explained:

  • int main(void) — every C program starts here. This is the function ("a named block of code") that runs first.
  • setup() and loop() aren't special C keywords — they're just names we chose for two functions we'll write ourselves, to keep "run once" code separate from "run forever" code.
  • while (1) { ... } — a loop that never stops, because 1 always means "true." On a desktop, a program that never ends would be a bug. On a chip, it's the point: as long as it has power, it should keep working.
  • // starts a comment — text the compiler ignores, there for humans reading the code.
Why no "end"? On your laptop, when a program finishes, control goes back to the operating system. A microcontroller usually has no operating system to go back to — so the program simply loops forever, reacting to the world, until the power is cut.

04 Variables & Data Types

A variable is a labeled box that holds a value. The type says what kind of value fits in the box, and how big the box is.

variables.c
int count = 0;          // a whole number
float voltage = 3.3f;   // a number with a decimal point
char letter = 'A';    // a single character

The basic types, in plain terms:

The types you'll actually use on a chip

Here's something specific to embedded C: on a microcontroller, memory is precious, so we usually pick a type by exactly how many bits it needs — not just "int" and hoping for the best. These come from a header file called <stdint.h>:

exact-types.c
#include <stdint.h>

uint8_t  brightness = 200;   // 8 bits → holds 0 to 255
int8_t   temp_c     = -10;    // 8 bits, but can go negative: -128 to 127
uint16_t reading    = 4095;   // 16 bits → holds 0 to 65,535
uint32_t milliseconds = 0;   // 32 bits → holds a much bigger number

Read uint8_t as "unsigned integer, 8 bits, type." The "u" means it can't be negative. Once you know that pattern, all the others (int16_t, uint32_t...) read themselves.

Beginner tip When you're not sure which to use yet, plain int is fine for learning and small test programs. Once you're writing real embedded code, switch to the exact-size types above — professionals use them almost everywhere.

The #1 beginner trip-up = means "store this value." == means "are these equal?" They look similar but do completely different things — mixing them up is the most common bug new C programmers write.

06 Making Decisions

if, else, and switch let your program choose what to do.

decisions.c
uint16_t temperature = 85;

if (temperature > 80) {
    turn_on_fan();
} else if (temperature > 60) {
    idle();
} else {
    turn_off_fan();
}

Read it out loud like English: "if temperature is greater than 80, turn on the fan; otherwise if it's greater than 60, idle; otherwise, turn off the fan." That's really all if/else if/else is.

When you're checking one variable against many exact values, switch is often cleaner:

switch.c
switch (button_id) {
    case 1: start_motor(); break;
    case 2: stop_motor();  break;
    default: do_nothing();  break;
}

Don't forget break; — without it, C keeps running the next case too, which almost never is what you want.

07 Repeating Things: Loops

loops.c
// "for" — repeat a known number of times
for (uint8_t i = 0; i < 10; i++) {
    blink_led();
}

// "while" — repeat as long as something is true
while (button_is_pressed()) {
    count_up();
}

A for loop packs "start, condition, step" into one line — good when you know how many times to repeat. A while loop just keeps going as long as its condition is true — good when you don't know the count in advance, only the stopping rule.

08 Functions

A function is a named, reusable chunk of code — you already used two: setup() and loop().

functions.c
uint16_t add_offset(uint16_t raw, uint16_t offset) {
    return raw + offset;
}

void blink_led(void) {
    // no input, no return value — it just *does* something
}

Break it down: uint16_t before the name is what the function gives back (its return type). void means "gives back nothing." The stuff in the parentheses — uint16_t raw, uint16_t offset — are the inputs, called parameters. Inside the { } is what the function actually does.

09 Pointers, Gently

The idea that scares every beginner, explained without the scary part: a pointer just stores an address, not a value.

Every variable lives somewhere in memory — at an address, like a house number. A normal variable holds a value. A pointer holds the address of a value.

pointers.c
uint8_t brightness = 50;     // a normal variable — holds a value
uint8_t *p = &brightness;  // p holds brightness's ADDRESS ("&" means "address of")

*p = 80;                    // "*p" means "go to that address and write here"
                              // this changes brightness to 80, through p
Analogy Think of a variable as a house, and its value as what's inside. A pointer isn't the house — it's a sticky note with the house's address written on it. & means "give me the address." * means "go to the address and look inside (or write there)."

Why bother? Because in embedded C, a pointer is how you reach a specific piece of hardware — every pin and peripheral on the chip lives at a fixed address, and a pointer is how your code gets there. We'll use exactly this idea in section 13.

10 Arrays & Strings

arrays.c
uint8_t readings[5];     // a box holding 5 uint8_t values, side by side
readings[0] = 12;       // arrays start counting from 0, not 1
readings[1] = 45;

const char *message = "READY";  // text in C is just an array of characters

An array is a numbered row of boxes of the same type. readings[0] is the first box, readings[1] the second, and so on — the count always starts at 0. Text ("strings") in C are simply arrays of char, ending with a hidden zero that marks "the text stops here."

11 Structs: Grouping Data

A struct bundles related variables into one labeled package.

struct.c
typedef struct {
    uint16_t x;
    uint16_t y;
} Point_t;

Point_t p1 = { .x = 10, .y = 20 };
p1.x = 15;   // "." reaches inside the struct to a specific field

Instead of tracking x and y as two separate loose variables, a struct keeps them together as one thing — a Point_t. This becomes very useful once one "thing" (like a sensor) has several properties at once.

12 Bits, Bytes & Binary

Computers only really understand two values: on and off. Everything else is built from that.

A bit is a single 0 or 1. A byte is 8 bits grouped together — enough to count from 0 to 255. When we write uint8_t, we mean exactly one byte, exactly 8 bits.

0b7
0b6
0b5
0b4
1b3
0b2
0b1
0b0
Eight bits, one lit up (bit 3) — this pattern equals the number 8.

In embedded C, we often care about individual bits — one bit might mean "is this pin on," another "is this alarm active." The tools for that:

bits.c
uint8_t flags = 0;

flags |= (1 << 3);   // turn ON bit 3
flags &= ~(1 << 3);  // turn OFF bit 3

if (flags & (1 << 3)) {  // CHECK if bit 3 is on
    // it is!
}

1 << 3 reads as "take the number 1, and shift it left 3 places" — which produces a value with only bit 3 turned on. You don't need to memorize this instantly; you'll type it enough times that it becomes automatic.

13 Talking to Hardware

This is where pointers (section 9) and bits (section 12) come together to actually control something.

Every pin and hardware feature on a microcontroller is controlled by writing to a specific memory address — called a register. Writing the right bit pattern to the right address turns a pin on or off. This is exactly the "pointer to an address" idea from earlier, just aimed at hardware instead of a normal variable.

register.c
// this line means: "treat address 0x40020014 as a uint32_t I can write to"
#define LED_PORT (*(volatile uint32_t *)0x40020014)

LED_PORT |= (1 << 5);   // turn ON pin 5, using the bit trick from section 12

One new word: volatile. It tells the compiler "this value can change for reasons you can't see (real hardware), so don't get clever — always read it fresh." Every hardware register in embedded C is marked volatile for this reason.

You don't need to memorize addresses Chip manufacturers provide header files with friendly names already defined (like GPIOA instead of 0x40020000) — you'll use those in real projects, not raw addresses.

14 First Project: Blink an LED

Every piece above, put together.

blink.c
#include <stdint.h>

#define LED_PIN     5u
#define LED_MODE    (*(volatile uint32_t *)0x40020000)  // sets pin as output
#define LED_PORT    (*(volatile uint32_t *)0x40020014)  // turns pin on/off

void delay(uint32_t count) {
    while (count--) { /* just wastes time, on purpose */ }
}

int main(void) {
    LED_MODE |= (1 << (LED_PIN * 2));  // step 1: tell the pin "you're an output"

    while (1) {                       // step 2: loop forever
        LED_PORT ^= (1 << LED_PIN);       // step 3: flip the LED's pin (^ toggles it)
        delay(500000);                   // step 4: wait a bit before flipping again
    }
}

Walk through it slowly: we tell one pin "you're an output, not an input." Then, forever, we flip that pin's state (on→off, off→on) and pause between flips. That pause is the difference between a blink you can see and a flicker too fast to notice. Real projects use a proper timer instead of a wasteful counting loop, but this version teaches the idea without extra machinery.

Note The addresses above (0x40020000...) are just examples in the style of one common chip family. Your actual board's addresses come from its datasheet or vendor header file — never guess them on real hardware.

15 What to Learn Next

You now have everything needed to read most beginner embedded C tutorials without getting lost.

  • Get real hardware. An Arduino Uno or an STM32 "Blue Pill"/Nucleo board are both cheap, well-documented starting points.
  • Interrupts. A way for hardware to "tap your code on the shoulder" instantly, instead of your code having to constantly check ("poll") for changes.
  • Timers. Built-in hardware clocks — the proper replacement for the wasteful delay() loop above.
  • UART/I2C/SPI. The common ways chips talk to other chips and sensors.
  • Reading a datasheet. A real skill — it's just a big reference table of registers and what each bit means.
You're ready Every advanced embedded C topic is built from the pieces in this course: variables, bits, pointers, and registers. Nothing after this is a new language — just new combinations of what you already know.
